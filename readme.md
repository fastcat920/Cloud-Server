# Cloud Desk

独立的自托管云资源工作台。原生 PHP + 浏览器 JavaScript，代码和 UI 全新编写，不再包含 Laravel、React、V2Board、Composer 或 Node.js 运行依赖。无数据库，根目录直接运行。

## 在网站当前目录部署与更新

**网站目录就是项目根目录。在哪个目录部署，后续命令就在同一目录执行，不增加 cloud-desk 子目录。**

例如网站目录为 `/www/wwwroot/cloud.fastcat.lol`。

### 首次安装：当前目录为空

在宝塔网站终端进入该目录，直接克隆到 `.`：

```sh
cd /www/wwwroot/cloud.fastcat.lol
git clone https://github.com/fastcat920/Cloud-Server.git .
```

最后一个点表示当前目录。若目录已有宝塔生成的默认页面，请先自行备份并移走，Git 不会克隆到非空目录。

宝塔网站目录保持 `/www/wwwroot/cloud.fastcat.lol`，运行目录保持 `/`，PHP 选择 **8.2 或以上**，伪静态留空，启用 HTTPS。打开域名创建管理员，不需要安装 Composer、Node.js、数据库或构建前端。

宝塔中需允许网站运行用户写入 `_core/data`（不存在时先创建），代码和 `.git` 可由执行 Git 的部署用户持有，无需把整个仓库交给 www。若使用 root 部署且网站运行用户是 www，可执行 `mkdir -p _core/data`、`chown www:www _core/data`、`chmod 700 _core/data`；只调整数据目录。

### 原生 v2 解压版：只用 Git 接入当前目录

仅适用于已有 `_core/Store.php` 的原生 v2，且当前没有 `.git`。请先从设置下载完整备份。这一步会把程序文件对齐主分支，保留被忽略的 `_core/data`；本地自定义代码请另外备份。**不要用于旧 `_app` 架构或已经存在 Git 仓库的目录。**

就在现有网站目录执行：

```sh
git init -b main
git remote add origin https://github.com/fastcat920/Cloud-Server.git
git fetch origin main
git reset --mixed origin/main
git restore --source=origin/main --worktree .
git branch --set-upstream-to=origin/main main
```

以后不需要重复初始化，仍在该目录执行 `git pull --ff-only origin main` 即可。Git 软件已安装和当前目录已是 Git 仓库是两个条件；解压包不会携带 `.git`。

### 已经通过解压包装好了原生 v2，但没有 .git（可选迁移工具）

无需换网站目录。在**当前网站目录**执行一次：

```sh
cd /www/wwwroot/cloud.fastcat.lol
curl -fsSL https://raw.githubusercontent.com/fastcat920/Cloud-Server/main/update.sh -o update.sh && bash update.sh
```

脚本会识别原生 v2，先把现有网站备份到网站目录之外，再在当前目录补齐 Git 仓库和代码。`_core/data` 内的账号、密钥、配置与历史记录保持不变。临时克隆发生在系统临时目录，结束后清理，不会在网站内增加一层项目目录。

此方式**不用于旧版 \_app / Laravel 结构**或其他网站；检测到这些目录时停止，不会覆盖。v1 数据仍通过「从 v1 迁移」的导入流程处理。

### 以后更新：仍在原来的目录

```sh
cd /www/wwwroot/cloud.fastcat.lol
git pull --ff-only origin main
```

请先从设置下载备份。Git 仅更新代码，不会覆盖忽略的 `_core/data`。此命令仅适用于首次通过 Git 克隆、或已接入 Git 的目录。

如果希望升级前自动备份，可选执行 `bash update.sh`。脚本检查远端、分支和本地代码修改，获取最新代码，升级前备份，然后只做快进更新。出现本地修改、历史分叉、仓库不匹配或下载失败时停止，不会强制重置。已是最新版时不会重复备份。

原生 `git pull` 不会自动备份。不要执行 `git clean -fdx`，它会删除被忽略的数据目录。

备份位于网站父目录的 `.cloud-desk-backups/`，目录权限 0700、归档权限 0600。备份包含数据和密钥，应妥善保管；脚本不会自动删除旧备份。

程序使用 OpenSSL 和 curl；对象存储需要 SimpleXML，Ed25519 模式需要 sodium。无需 Redis、定时任务或常驻进程。

对象存储默认不修改对象 ACL。发布目标中可明确开启“公开可读”；签名读取校验只验证对象内容，CDN 或自定义公开地址是否可访问仍需自行确认。上传单文件限制 20 MB，下载限制 32 MB；PHP 和 Nginx 的上传大小限制也应相应设置。更大的文件使用云厂商工具处理。

## 客户端配置：方案、结构模板与发布修订

内置「FastCat OSS 默认结构」按 `_core/client-defaults.json` 提供完整参数和默认示例，包括 legal、contact.fastcat_support 和六个平台的更新及 artifacts 安装包。新安装直接使用此结构；已有安装自动追加模板，并更新原有兼容方案的新草稿默认模板，不改写已有修订或自定义方案模板。点击「按默认模板新建」生成完整草稿；普通「新建草稿」仍参考当前修订。新方案默认选择该模板。示例域名、版本、App Store ID、SHA256 等需要核实替换，不会自动发布。


字段支持同组拖拽和上移、下移。对象字段顺序作为修订设置保存，同步到结构表单、完整 JSON 及发布文件；未指定顺序的字段保留原有顺序；数组调整会改变实际内容顺序。彻底删除会移除当前修订中的值、子项、字段定义和对应必填约束，保存后生效。共享模板与历史修订保持独立，复制和回滚保留排序。数组各项共用 items 结构定义，调整某项的字段定义会作用于当前修订内该数组的校验结构。


日常编辑无需编写 JSON：展开参数组逐项填写，在列表中点击「添加一项」，或在参数组内点击「添加参数」选择名称和类型。已有未知参数会保留；模板禁止额外字段时需先升级模板。完整 JSON 作为高级编辑入口保留。文件大小使用字节。更新校验同时兼容旧版直接 url 和新版 artifacts 安装包列表。


- **配置方案**：为客户端版本线（例如 1.x、2.x）建立独立方案，新建时可直接以当前已保存修订为基础并保留原结构，标记适用版本并绑定独立发布目标。版本范围是管理标签，不会自动识别客户端；客户端需请求对应方案的对象地址。
- **结构模板**：使用 JSON Schema 子集定义字段，支持 type、properties、required、enum、items、minimum、minLength、default、additionalProperties 以及标题说明。不支持的关键字会拒绝保存。每次保存模板都生成新模板，已有模板不会被修改。
- **结构快照**：每个修订保留自己的结构，旧修订不会随默认模板变化。表单读取结构快照，对象与数组逐层展开为可视化表单，支持逐项增删和填写，布尔值使用开关，数字使用数值输入，完整 JSON 入口始终保留。模板外参数不会被丢弃；可选参数缺失时不会自动补入。
- **发布修订**：草稿可以反复保存；编辑已发布、部分失败或归档修订时，保存会生成新草稿，保留历史原文。支持保存并推送、已保存修订差异、本次未保存变更预览、基于历史修订回滚并推送。
- **结构升级**：显式选择目标模板后，只补入缺少且声明 default 的字段。删除参数必须填写路径（例如 contact.old_key），预览新增、删除和变化并确认；确认后还需要保存。不会自动转换已有字段类型。
- **发布隔离**：目标需先在方案设置中绑定；不同方案不能共用相同发布路径。成功发布仅归档同一方案的旧当前版本。回滚基于历史内容和结构新建修订，再推送至该方案当前绑定目标。

升级后原有配置自动归入「默认客户端配置」，每个历史版本保留自己的字段快照。原有发布目标首次归入默认方案；之后新增目标需要手工绑定。默认兼容结构中的 config_version 继续随内部版本递增；自定义结构里的同名参数按用户内容保留。备份、恢复与旧版导入包含方案和模板迁移。

新模板示例：

```json
{
  "type": "object",
  "properties": {
    "api_url": { "type": "string", "title": "API 地址" },
    "timeout": { "type": "integer", "minimum": 1, "default": 30 },
    "backup_urls": { "type": "array", "items": { "type": "string" } }
  },
  "required": ["api_url"],
  "additionalProperties": true
}
```

## 从 v1 迁移

v2 是全新架构，**建议在新目录 Git 克隆**，保留旧站作为迁移对照。不要把新版文件直接覆盖到旧 `_app` 结构中。

1. 备份旧 `_app/.env` 和 `_app/storage/app/private/state.json`。
2. 在新版创建管理员，进入「设置 → 导入旧版数据」。
3. 上传旧 `state.json`，填写旧 `.env` 中的 APP_KEY，确认导入。
4. 迁移统一账号、独立 DNS / Cloudflare 凭证、配置版本、发布目标、XOR / 签名密钥和发布历史。相同凭证自动合并；当前管理员账号保持不变。

仅允许向尚未添加云账号和发布目标的新安装导入。旧版发布目标的“公开可读”默认关闭，请在新页面核对访问策略。

## 数据保护与备份

- 云凭证采用 AES-256-GCM 加密。密码使用 PHP 密码哈希，会话使用 HttpOnly / SameSite Cookie，所有写接口检查 CSRF。
- 本地快照采用文件锁和原子替换，读取损坏数据时拒绝继续写入。敏感数据、锁和会话文件都有 PHP 拒绝访问保护，不依赖伪静态规则来隐藏数据。
- `_core/data/key.php` 是解密密钥，必须与数据一起备份，丢失后无法解密账号凭证。
- 「下载完整备份」包含凭证及解密密钥，请离线妥善保存。恢复会覆盖资源配置，保留当前管理员登录信息。
- 本项目适合单机、少量管理员使用。PHP 必须正常启用，不能把此仓库部署为纯静态网站。

## 开发与验证

所有页面为原生 ES 模块，无需安装前端依赖。修改文件后刷新即可；新 UI 包含响应式布局、原生对话框和键盘焦点。

```sh
php tests/unit.php
PHP_BINARY=php python3 tests/integration.py
php -S 127.0.0.1:8080 -t .
```

`tests/unit.php` 覆盖原子读写、并发、加密、三厂商请求与资源数据映射、XML 分页、客户端配置输出及旧数据导入。集成测试使用隔离目录和模拟云服务，覆盖初始化、会话、CSRF、统一凭证、发布校验、备份恢复和授权控制，不访问真实云资源。

真实云凭证未在开发机联调。上线后应先使用权限明确的测试资源验证。云厂商接口权限、账号站点和资源地域均会影响可见范围。

## 发布与恢复保护

发布采用单实例全局文件锁；同一时间只允许一个发布、恢复或关键目标设置变更。每个目标冻结最终输出、目标地址和加密凭证快照，保存步骤进度。中断任务会在打开概览或下一次发布时标为可重试失败；重试复用原输出，不受密钥轮换影响。目标变化、解除绑定或该地址已有更新成功任务时拒绝旧任务重试，需重新选择修订发布。任务仍由 HTTP 请求执行，没有引入常驻队列；超时后需重试，并不会自动后台继续。

编辑现有修订必须提交 overview 返回的 edit_token 作为 expected_token，过期保存返回 409；页面不会强制覆盖。恢复前验证 ID、引用、结构和排序，并在 `_core/data/backups/` 保存带 PHP 保护头、权限 0600 的完整恢复前快照，自动备份失败时不执行恢复。这些快照含恢复密钥，应按凭证文件保护，暂不自动清理。

发布前拒绝内置配置中的示例/占位参数，检查更新来源、版本号、构建号、App Store ID、安装包 SHA256 和大小。停用的参数组不检查其占位值；草稿仍可保存未填写完的内容。所有输出模式都在冻结后上传并校验。

## GTM 3.0 可视化管理

「流量调度」使用已有阿里云账号，按接入域名、地址池、地址、探测模板和变更记录分类。查询后点击「可视化配置」，查看接入域名→地址池→地址的拓扑，点击整张节点卡片即可在当前画布旁编辑；配置、策略、关联、启停等字段集中在同一个表单，关联的探测模板也可直接打开。节点以浅红、浅橙、浅绿显示异常、部分异常、正常，未知状态保持中性色。常用基础配置、负载策略、关联列表、权重/顺序/请求来源、启停、备注和人工切换均使用表单；探测节点、协议参数与健康检查端口逐项填写，无需编辑 API JSON。

地址池、地址、探测模板列表使用“编辑”入口打开右侧抽屉，标题和提交按钮固定，中间表单独立滚动；手机端全屏显示。关闭或保存后回到原列表位置，未保存修改会在关闭前提醒；保存后刷新当前列表；接入域名保留可视化画布入口。设置按基础信息、启停与调度、健康检查、关联资源、备注排列，资源操作置于末尾。切换策略、故障切换模式和线路选择时保留当前滚动位置与输入焦点。

设置和资源选项只显示名称，配置标识保留在内部请求中。按父级负载策略显示关联项：顺序策略显示优先序号，权重策略显示权重，来源就近保留用于同线路优先级的序号。切换策略时隐藏字段的已有值仍会保留。

探测节点使用“已选标签＋节点分组→城市→运营商”逐级选择，可跨分组搜索、多选和移除。选择器收起或切换层级时保留全部已选节点，目录暂时缺失的原有节点也不会自动删除。IPv4 与 IPv6 使用各自的节点目录；节点及搜索结果每级最多显示 80 项，避免一次渲染完整目录。

请求来源使用已选标签和按需打开的层级选择器，按系统线路的父子关系逐级展开，支持搜索地区或运营商。搜索结果最多渲染 80 项，避免大线路列表阻塞表单。表单先读取实时详情，地址、地址池、实例、探测模板等选项与详情并行预加载，首个画布同时预取探测模板目录；查询结果会同步填充当前表单中的全部同类下拉框，不必逐个点击。可见线路标签也会提前加载名称，线路树仍按需展开；资源选项在同一账号下缓存 30 秒，线路与探测节点缓存 10 分钟，失败不缓存，提交成功后清理。加载或失败时保留已选引用，失败支持就地重试。打开画布不再额外查询引用；预览仍实时查询引用范围，预览和提交均实时校验配置冲突。

接入域名创建仅绑定已购实例（prepay），不涉及购买实例。新建资源默认禁用，完成配置后可显式启用。地址池和地址是账号级共享资源：预览显示引用数量，被引用资源不允许直接删除，需在上级关联表单移除后提交。关联列表是完整替换，清空表示解除全部引用。

变更预览和历史详情只列出实际修改的字段，关联列表按资源 ID 对比，单独显示新增、移除和优先序号变化。修改先生成十分钟有效的加密预览凭证；提交时重新检查云端配置摘要，同账号写操作使用文件锁，确认凭证可幂等提交。云端健康状态和探测时间变化不计入编辑冲突。提交后重新查询，只有字段校验一致才显示确认成功，否则显示已提交并提示刷新；多项配置按接口逐步提交，每步重新检查冲突并确认保存结果；发生失败或尚未确认时停止后续步骤，提示部分提交状态，不承诺跨接口事务回滚。DNS 缓存不会因此立即失效。本地保留最近 200 条 GTM 变更及修改前快照，完整备份包含这些记录。

画布及编辑详情在浏览器内按账号和查询批次缓存 15 秒，合并进行中的相同请求；首个接入域名和鼠标停留的资源会有限预取。刷新画布强制重新查询，写入后失效缓存。编辑框会先显示加载面板，查询失败可关闭或重试。编辑缓存不用于提交校验，预览和提交仍读取云端检查冲突。

同一预览内合并重复详情和引用读取，只提交已修改字段、切换模式必需的关联字段及接口要求的标识；每个写入步骤仍保留提交前检查和提交后回读。保存画布内资源不再额外刷新整个列表：同一根资源使用已校验的回读结果，其他情况只重新查询根画布。GTM 请求复用本次 PHP 请求内的 HTTPS 连接并支持压缩；响应中的 `Server-Timing` 提供 GTM 处理耗时、云端耗时及调用次数，便于定位服务器至阿里云的网络延迟。

修改地址的健康探测任务时，会同时携带当前健康判定条件；自动补齐的关联字段在生成预览凭证前冻结，提交时不会静默改变已确认参数。GTM 错误默认显示中文，云端错误码、请求编号和原始错误保存在折叠的“技术详情”与变更记录中；写入失败时同时保留实际发送的业务参数（JSON 字符串保持发送格式）及修改前地址配置，排除 AccessKey、签名和幂等令牌；通用参数错误不会直接断言是某一个字段导致。变更预览及详情使用中文字段名和可读取的资源名称。

接口字段依据阿里云官方 OpenAPI 元数据维护于 `_core/gtm-operations.json`，运行时无需联网下载定义。参考：

需要相应的 GTM 读取和修改 RAM 权限。测试使用隔离的模拟云服务，正式账号的配额、套餐能力和实际权限需以阿里云返回为准。当前范围为 GTM 3.0，不调用 GTM 2.0 接口。

关联编辑中的「解除引用」只移除当前父资源的引用，不会删除全局地址或地址池；「全局删除」会检查上级引用并拒绝删除仍被使用的资源。增删和排序会保留其他关联项的权重、线路等参数。上移/下移将写入 SerialNumber 优先序号，重新打开时按该序号显示；该序号只有在顺序/主备负载策略下才决定优先调度，权重策略仍以权重为准。

共享地址的端口或探测绑定修改会作用于所有引用该地址的地址池；共享探测模板修改会作用于所有绑定该模板的地址。确认页列出受影响的引用资源。保存后查询确认配置字段一致，不代表探测立即变为健康，真实探测结果还需等待阿里云探测周期。

GTM 可视化工作区使用从上到下的树：域名→地址池→地址，并用连接线标明归属。点击树中任一节点或地址上的探测模板标签，直接在右侧面板编辑，保存后刷新原画布，不再逐级切换详情。画布内可以横向和纵向滚动；窄屏时编辑面板排列在画布下方。

域名的「新增地址池」和地址池的「新增地址」保留父节点上下文：先确认创建，再在当前父节点的关联列表中确认绑定。新资源创建成功但尚未确认绑定时，会明确提示；不自动覆盖其他关联项。
