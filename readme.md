# Cloud Server

独立管理客户端配置、阿里云解析、Cloudflare 解析、云账号。保留 catboard 的四个页面和云平台业务逻辑，改用本地 JSON 文件保存数据，不需要 MySQL、SQLite、Redis 或队列进程。

## 统一云账号与资源管理

- 所有访问密钥在「云账号管理」维护。客户端存储目标、云解析通过下拉框关联账号；更新密钥后自动共用新凭证。存储目标可读取账号下已有 Bucket，自动填写 Bucket 与 Endpoint。
- 旧配置首次打开对应概览时迁移到统一账号。仅厂商、AccessKey、Secret、临时令牌全部相同的凭证合并；不能解密的旧配置保留，不会清空。建议升级前备份。
- 被引用的账号不能删除或更换厂商；停用账号会阻止后续云请求。新增账号只保存凭证，余额在点击刷新时查询，账单权限不影响资源权限。
- 点击账号卡片「资源」，支持阿里云 ECS、腾讯云 CVM、UCloud UHost 的按地域分页查询、开机、关机、重启。UCloud 支持填写项目 ID。操作为异步提交，需刷新确认最终状态。
- 对象存储支持阿里云 OSS、腾讯云 COS、UCloud US3：Bucket 列表、目录浏览、前缀查找、分页、上传（单文件 20 MB）、下载及单文件删除。只列出当前凭证有权访问的资源，不会自动提高权限。
- 没有列举 Bucket 权限时，可输入已授权的 Bucket 名称及地域；US3 使用存储地域（例如 cn-bj），不一定与 UHost 地域相同。
- 上传保持云端默认访问控制，不自动公开文件；上传前确认可能覆盖同名文件。PHP 的 upload_max_filesize/post_max_size 及 Nginx client_max_body_size 也应允许相应文件大小。
- 操作记录保留最近 1000 条成功提交的管理操作，页面按账号展示最近 100 条。没有包含服务器终端、创建/销毁实例、修改安全组等功能。

真实云账号未在本机联调。已验证本地迁移及密钥引用、三厂商服务器响应和操作映射、存储 XML 分页解析与模拟上传删除；部署后请使用权限明确的测试资源验证。

## 宝塔安装（网站根目录直接运行）

1. 宝塔创建 PHP 8.2 网站并绑定域名，将 ZIP **直接解压到该网站目录**。解压后应直接看到 `index.php`、`assets` 和 `_app`，不要再套一层目录。运行目录保持默认 `/`，无需设为 public。
2. 在「伪静态 / URL 重写」中粘贴以下**完整内容**，不要填写文件名：

```nginx
location ^~ /_app/ {
    deny all;
}
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

第一条规则禁止外部访问应用代码、配置和数据，必须保留。第二条使登录及接口地址能进入程序。解压文件 `nginx-rules.txt` 中也有同样规则。

3. 启用 HTTPS 后打开域名，在网页创建管理员账号和密码。以后直接显示登录界面，无需终端命令。

宝塔文件管理中将解压后的文件所有者设为网站运行用户（通常 www）；`_app` 首次需可写以生成配置，`_app/storage` 和 `_app/bootstrap/cache` 需持续可写。若宝塔开启 open_basedir，需允许网站目录。缺少 PHP 扩展时在 PHP 设置中启用。

`_app` 是内部程序目录，不是网站运行目录。不能删除。网站访问入口仅为根目录 `index.php`。

忘记密码可在 `_app` 目录运行 `sudo -u www /www/server/php/82/bin/php install.php`。

## 更新

先备份 `.env` 与 `storage`，进入维护模式或停止网站写入。将新包中的程序文件覆盖到项目目录，保留现有 `_app/.env`、整个 `_app/storage` 目录，清理 `_app/bootstrap/cache` 中生成的 PHP 缓存后恢复网站。更新无需重新初始化或生成密钥。

## 从源码生成部署包

这是开发电脑上的操作，服务器不需要执行：先安装 Composer 依赖、构建前端，然后执行 `python3 tools/package-release.py`。输出完整 ZIP 与 SHA-256 校验文件，自动排除真实 `.env`、本地数据、日志、缓存、前端开发依赖和本机符号链接。PHP 依赖为跨平台源码，包中没有 macOS 可执行文件。

## 存储与备份

完整部署包的业务数据保存在 `_app/storage/app/private/state.json`，密码保存哈希，云密钥仍使用 APP_KEY 加密。该目录位于 public 之外，默认目录权限 0700、数据文件 0600。缓存和登录会话使用 Laravel 文件缓存。

写操作持有独立文件锁，整份快照通过临时文件原子替换；异常不提交，损坏的 JSON 会报错，不会静默清空。单机少量管理员使用；云发布期间会串行等待，PHP/Nginx 应配置足够超时时间。

备份必须同时保存 `_app/.env` 和 `_app/storage/app/private`；备份时停止写操作或先进入维护模式。丢失 APP_KEY 无法解密云密钥，升级不要重新生成。旧数据库版的数据不会自动导入，应在新项目重新添加账号及配置。

项目仍复用 Laravel 的属性转换、校验和 HTTP 能力，数据读写由本地存储层实现。真实云 API 需要使用自己的账号在部署环境完成联调。
