# Cloud Desk

独立的自托管云资源工作台。原生 PHP + 浏览器 JavaScript，代码和 UI 全新编写，不再包含 Laravel、React、V2Board、Composer 或 Node.js 运行依赖。无数据库，根目录直接运行。

## 在网站当前目录部署与更新

**网站目录就是项目根目录。在哪个目录部署，后续命令就在同一目录执行，不增加 cloud-desk 子目录。**

例如网站目录为 `/www/wwwroot/cloud.fastcat.lol`。

### 首次安装：当前目录为空

在宝塔网站终端进入该目录，直接克隆到 `.`：

```sh
cd /www/wwwroot/cloud.fastcat.lol
git clone https://github.com/fastcat920/Cloud-Server.git .
```

最后一个点表示当前目录。若目录已有宝塔生成的默认页面，请先自行备份并移走，Git 不会克隆到非空目录。

宝塔网站目录保持 `/www/wwwroot/cloud.fastcat.lol`，运行目录保持 `/`，PHP 选择 **8.2 或以上**，伪静态留空，启用 HTTPS。打开域名创建管理员，不需要安装 Composer、Node.js、数据库或构建前端。

宝塔中需允许网站运行用户写入 `_core/data`（不存在时先创建），代码和 `.git` 可由执行 Git 的部署用户持有，无需把整个仓库交给 www。若使用 root 部署且网站运行用户是 www，可执行 `mkdir -p _core/data`、`chown www:www _core/data`、`chmod 700 _core/data`；只调整数据目录。

### 已经通过解压包装好了原生 v2，但没有 .git（可选迁移工具）

无需换网站目录。在**当前网站目录**执行一次：

```sh
cd /www/wwwroot/cloud.fastcat.lol
curl -fsSL https://raw.githubusercontent.com/fastcat920/Cloud-Server/main/update.sh -o update.sh && bash update.sh
```

脚本会识别原生 v2，先把现有网站备份到网站目录之外，再在当前目录补齐 Git 仓库和代码。`_core/data` 内的账号、密钥、配置与历史记录保持不变。临时克隆发生在系统临时目录，结束后清理，不会在网站内增加一层项目目录。

此方式**不用于旧版 \_app / Laravel 结构**或其他网站；检测到这些目录时停止，不会覆盖。v1 数据仍通过「从 v1 迁移」的导入流程处理。

### 以后更新：仍在原来的目录

```sh
cd /www/wwwroot/cloud.fastcat.lol
git pull --ff-only origin main
```

请先从设置下载备份。Git 仅更新代码，不会覆盖忽略的 `_core/data`。此命令仅适用于首次通过 Git 克隆、或已接入 Git 的目录。

如果希望升级前自动备份，可选执行 `bash update.sh`。脚本检查远端、分支和本地代码修改，获取最新代码，升级前备份，然后只做快进更新。出现本地修改、历史分叉、仓库不匹配或下载失败时停止，不会强制重置。已是最新版时不会重复备份。

原生 `git pull` 不会自动备份。不要执行 `git clean -fdx`，它会删除被忽略的数据目录。

备份位于网站父目录的 `.cloud-desk-backups/`，目录权限 0700、归档权限 0600。备份包含数据和密钥，应妥善保管；脚本不会自动删除旧备份。

程序使用 OpenSSL 和 curl；对象存储需要 SimpleXML，Ed25519 模式需要 sodium。无需 Redis、定时任务或常驻进程。

## 功能

| 模块       | 支持范围                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------- |
| 云账号     | 阿里云、腾讯云、UCloud、Cloudflare；统一加密保存凭证，各模块直接引用                                                    |
| 余额与消费 | 查询余额、本月与上月消费；账单权限与其他资源权限独立                                                                    |
| 服务器     | ECS、CVM、UHost；按地域与项目分页查询，开机、关机、重启                                                                 |
| 对象存储   | OSS、COS、US3；Bucket 列表、目录与前缀查询、分页、上传、下载、删除                                                      |
| 云解析     | 阿里云域名与解析记录增删改                                                                                              |
| GTM        | 实例完整信息、地址池、地址与监控模板；策略、启停、绑定替换、备注和手动可用状态等操作。高级修改使用 API 字段 JSON 编辑器 |
| Cloudflare | Token 验证、域名分页、DNS 记录增删改、代理开关，以及高级记录参数                                                        |
| 客户端配置 | 可视化 / 完整 JSON 编辑、草稿版本、复制、预览、多目标发布、版本文件、失败重试与历史记录                                 |
| 配置输出   | 明文 JSON、XOR + Base64、Ed25519 签名的 fastcat-config-v2 兼容协议                                                      |
| 维护       | 密码修改、全量备份 / 恢复、旧版凭证和配置导入、操作记录                                                                 |

服务器操作为异步请求，提交成功不等于操作完成，请刷新查看最终状态。没有服务器 SSH 终端、创建/销毁实例或修改安全组功能。

对象存储默认不修改对象 ACL。发布目标中可明确开启“公开可读”；签名读取校验只验证对象内容，CDN 或自定义公开地址是否可访问仍需自行确认。上传单文件限制 20 MB，下载限制 32 MB；PHP 和 Nginx 的上传大小限制也应相应设置。更大的文件使用云厂商工具处理。

## 客户端配置：方案、结构模板与发布修订

- **配置方案**：为客户端版本线（例如 1.x、2.x）建立独立方案，新建时可直接以当前已保存修订为基础并保留原结构，标记适用版本并绑定独立发布目标。版本范围是管理标签，不会自动识别客户端；客户端需请求对应方案的对象地址。
- **结构模板**：使用 JSON Schema 子集定义字段，支持 type、properties、required、enum、items、minimum、minLength、default、additionalProperties 以及标题说明。不支持的关键字会拒绝保存。每次保存模板都生成新模板，已有模板不会被修改。
- **结构快照**：每个修订保留自己的结构，旧修订不会随默认模板变化。表单读取结构快照，复杂对象与数组使用 JSON 字段编辑，完整 JSON 入口始终保留。模板外参数不会被丢弃；可选参数缺失时不会自动补入。
- **发布修订**：草稿可以反复保存；编辑已发布、部分失败或归档修订时，保存会生成新草稿，保留历史原文。支持保存并推送、已保存修订差异、本次未保存变更预览、基于历史修订回滚并推送。
- **结构升级**：显式选择目标模板后，只补入缺少且声明 default 的字段。删除参数必须填写路径（例如 contact.old_key），预览新增、删除和变化并确认；确认后还需要保存。不会自动转换已有字段类型。
- **发布隔离**：目标需先在方案设置中绑定；不同方案不能共用相同发布路径。成功发布仅归档同一方案的旧当前版本。回滚基于历史内容和结构新建修订，再推送至该方案当前绑定目标。

升级后原有配置自动归入「默认客户端配置」，每个历史版本保留自己的字段快照。原有发布目标首次归入默认方案；之后新增目标需要手工绑定。默认兼容结构中的 config_version 继续随内部版本递增；自定义结构里的同名参数按用户内容保留。备份、恢复与旧版导入包含方案和模板迁移。

新模板示例：

```json
{
  "type": "object",
  "properties": {
    "api_url": { "type": "string", "title": "API 地址" },
    "timeout": { "type": "integer", "minimum": 1, "default": 30 },
    "backup_urls": { "type": "array", "items": { "type": "string" } }
  },
  "required": ["api_url"],
  "additionalProperties": true
}
```

## 从 v1 迁移

v2 是全新架构，**建议在新目录 Git 克隆**，保留旧站作为迁移对照。不要把新版文件直接覆盖到旧 `_app` 结构中。

1. 备份旧 `_app/.env` 和 `_app/storage/app/private/state.json`。
2. 在新版创建管理员，进入「设置 → 导入旧版数据」。
3. 上传旧 `state.json`，填写旧 `.env` 中的 APP_KEY，确认导入。
4. 迁移统一账号、独立 DNS / Cloudflare 凭证、配置版本、发布目标、XOR / 签名密钥和发布历史。相同凭证自动合并；当前管理员账号保持不变。

仅允许向尚未添加云账号和发布目标的新安装导入。旧版发布目标的“公开可读”默认关闭，请在新页面核对访问策略。

## 数据保护与备份

- 云凭证采用 AES-256-GCM 加密。密码使用 PHP 密码哈希，会话使用 HttpOnly / SameSite Cookie，所有写接口检查 CSRF。
- 本地快照采用文件锁和原子替换，读取损坏数据时拒绝继续写入。敏感数据、锁和会话文件都有 PHP 拒绝访问保护，不依赖伪静态规则来隐藏数据。
- `_core/data/key.php` 是解密密钥，必须与数据一起备份，丢失后无法解密账号凭证。
- 「下载完整备份」包含凭证及解密密钥，请离线妥善保存。恢复会覆盖资源配置，保留当前管理员登录信息。
- 本项目适合单机、少量管理员使用。PHP 必须正常启用，不能把此仓库部署为纯静态网站。

## 开发与验证

所有页面为原生 ES 模块，无需安装前端依赖。修改文件后刷新即可；新 UI 包含响应式布局、原生对话框和键盘焦点。

```sh
php tests/unit.php
PHP_BINARY=php python3 tests/integration.py
php -S 127.0.0.1:8080 -t .
```

`tests/unit.php` 覆盖原子读写、并发、加密、三厂商请求与资源数据映射、XML 分页、客户端配置输出及旧数据导入。集成测试使用隔离目录和模拟云服务，覆盖初始化、会话、CSRF、统一凭证、发布校验、备份恢复和授权控制，不访问真实云资源。

真实云凭证未在开发机联调。上线后应先使用权限明确的测试资源验证。云厂商接口权限、账号站点和资源地域均会影响可见范围。
